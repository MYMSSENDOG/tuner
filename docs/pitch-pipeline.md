# 음정 측정 파이프라인 상세

마이크에 소리가 닿는 순간부터 바늘이 움직이기까지의 전 과정.
예시는 바이올린이 **442Hz 근처의 A음**을 켜는 상황으로 통일한다.
각 단계의 구현 파일과 수치 근거를 함께 적는다.

```
마이크 → [0] 샘플링/버퍼링 → [1] 레벨 게이트 → [2] YIN 검출
       → [3] 스펙트럼 교차검증 → [4] Tracker 표시 정책
       → [5] Hz→음이름+cent → [6] 미터/트레이스
```

---

## 0. 소리가 숫자가 되기까지 — `audio/`, `app/engine.py`

- OS가 마이크 전압을 초당 44,100번 샘플링해 -1.0~+1.0 실수로 만든다.
- PortAudio(sounddevice)가 **256샘플(5.8ms) 블록** 단위로 콜백에 전달.
- 엔진은 최근 **2048샘플(46ms)을 링버퍼**로 유지하고, 블록이 올 때마다
  (= 5.8ms 주기, 초당 172회) 이 창 전체로 아래 과정을 1회 수행한다.
- 442Hz 의 한 주기 = 44100 ÷ 442 = **99.77샘플**. 46ms 창에 약 20.5주기.

## 1. 입력 레벨 게이트 — `core/detector.py`

프레임 RMS가 **-40dBFS**(풀스케일의 1%) 미만이면 판정하지 않는다
(unvoiced 반환). 활 잔향·룸 노이즈도 추적 가능한 피치를 갖고 있어서,
게이트 없이는 음 사이 공백에서 표시가 요동친다.

> 근거: 바이올린 스케일 실녹음(실제 5음)에서 게이트 레벨 스윕 —
> 게이트 없음 125회 표시 변경 / -40dBFS 정확히 5회 / -35dBFS 부터
> 진짜 음 잠식. UI 감도 설정은 두지 않는다(제품 방침).

## 2. YIN 검출 — `core/pitch.py` (심장부)

"파형을 몇 샘플 밀면 자기 자신과 겹치는가"로 주기를 직접 잰다.

검출기는 같은 버퍼에 창 두 개를 쓴다. 짧은 창(2048=46ms)이 기본이고
반응 속도를 결정한다. 다만 YIN 은 주기가 창의 절반 안에 들어와야 해서
2048 로는 ~60Hz 아래를 못 본다. 콘트라베이스 E1(41Hz)은 실재하는 튜닝
대상이므로, 짧은 창이 저역을 가리키거나 아무것도 못 찾으면 4096 전체를
한 번 더 본다(`LOW_FMIN_HZ=38`). 이 경로는 **저역 전용**이다 — 결과가
90Hz 이상이면 채택하지 않는다. 짧은 창의 노이즈 내성을 저역 확장과
바꾸지 않기 위해서다. 레벨 게이트·스펙트럼 교차검증도 판정에 쓴 창과
같은 구간을 본다(불일치 시 트럼펫+플루트 간섭에서 회귀가 났다).

### 2-1. Difference function

```
d(τ) = Σⱼ [x(j) − x(j+τ)]²    (τ = 0..1023)
```

주기 T인 신호는 τ=T에서 자기 자신과 겹쳐 d≈0. 정직한 계산은 O(n²)라
자기상관 전개(d = 에너지항 − 2×상관항)로 **FFT 한 번**에 계산한다.

### 2-2. CMNDF 정규화

d(τ)는 τ=0에서도 0이고 음량에 비례하므로, "누적 평균 대비 얼마나 깊은
골인가"로 정규화한다:

```
d′(τ) = d(τ) · τ / Σ₁..τ d
```

진짜 주기(와 그 배수들)에서 0~1 스케일의 깊은 **골(dip)** 이 파인다.

### 2-3. 어느 골이 진짜 주기인가 (옥타브 판정 — 승부처)

골은 여러 개다:
- **배수 골**(2T, 3T, …): T-주기 신호는 2T로 밀어도 겹침 → 고르면 옥타브 **아래** 오검출
- **약수 골**(T/2, T/3): 짝수 배음이 지배적이면 반주기로도 꽤 겹침 → 옥타브 **위** 오검출

3중 방어:

1. **보간 극소값으로 비교** (`_interpolated_dip`) — 주기가 99.77처럼
   비정수면 정수 lag의 샘플값은 양자화 페널티로 실제보다 얕게 보인다.
   골 주변 3점 포물선의 꼭짓점 깊이로 비교해야 서로 다른 lag끼리
   공정하다. (없으면 1661Hz에서 우연히 정수에 가까운 11×T 골이 이김 —
   실제 있었던 버그)
2. **최소 lag 우선 + 가산 마진** (`_prefer_smallest_period`) — 전역
   최소 골의 약수 위치들을 작은 lag부터 검사, 깊이가 "전역 최소 +0.08"
   이내면 채택. 노이즈 하에선 CMND 정규화 특성상 배수 골들이 전부
   비슷하게 깊어지는데, 그중 진짜는 최소 lag이다. 마진을 키우면
   깨끗한 음의 전환 구간이 깨지는 트레이드오프가 실측돼 있다
   (0.08 채택; 강한 비배음 간섭은 xfail로 문서화된 한계).
3. **배수 검증** (`_is_true_period`) — 진짜 주기라면 그 **모든 배수**에
   골이 있어야 한다. 간섭이 판 가짜 반주기 골은 1.5T에 골이 없어 탈락.
   probe 배수는 전역 최소와 자명하게 겹치지 않도록 선택(k=2면 3j, 그
   외 2j — k=6에서 3j=T가 되어 무의미했던 버그 수정).

### 2-4. 정밀화 (여기서 sub-cent가 나온다)

1. **포물선 보간**: d(99), d(100), d(101)의 포물선 꼭짓점 → τ≈99.8.
   고음에선 부족: E7(2637Hz)은 τ≈16.7이라 0.02샘플 오차가 2cent.
2. **고배수 lag 재보간** (`_refine_at_higher_lag`): 골은 m×τ에도 있으니
   창이 허용하는 최대 배수(예: m=10, τ≈998)에서 재보간 후 m으로 나눔 —
   **보간 오차가 1/m**. τ = 99.7738 수준으로 확정.

**freq = 44100 ÷ τ = 442.00Hz.** 클린 신호 오차 ±0.08cent.
함께 **confidence = 1 − 골 깊이** (클린 ~0.98, 노이즈 ~0.5-0.7).

## 3. 스펙트럼 교차검증 — `core/spectral.py`

YIN의 원리적 맹점: **기음이 극도로 약한 소리**(오보에 F5는 2배음이
기음의 8배)는 신호가 거의 반주기-주기적이라 시간 영역만으로 T와 T/2를
구분할 수 없다. 매 프레임 FFT 1회로 확인한다
(`restore_weak_fundamental` → `divide_to_true_f0`):

- YIN이 답한 f의 **배음 빗(comb, 각 배음 ±주엽폭)** 이 스펙트럼 에너지를
  얼마나 덮는지 계산.
- f/2(또는 /3) 빗으로 바꿨을 때 **사이사이의 실재 배음**(홀수 배음)이
  에너지를 **1.2%p 이상** 더 잡으면 진짜 기음은 그 아래 — 나눠서 복원.
- 광대역 노이즈도 빗 사이에 에너지를 흘리므로, 평평한 스펙트럼이 만들
  기대 이득의 **3배**를 넘어야 인정(적응형 게이트).

> 근거: 오보에 스케일 Bb4(3배음 지배) 189미스 → 0. 오보에 F5(2배음
> 8배, 홀수 콤 에너지 1.8%)가 2% 게이트를 간발로 탈락해 1.2%로 보정 —
> 클린 잡음 바닥 ~0.3%와 양쪽 여유. 같은 로직이 오프라인 주석기
> (`analysis/reference.py`)에서는 게이트 10%로 돈다.

같은 파일의 `estimate_f0`(HPS + 배음별 연속 DTFT 탐색)는 이 로직의
완전판으로, 테스트 정답 생성기(주석기)와 Spectral 검출기의 본체다.

## 4. Tracker: 측정값 → 표시값 — `core/tracker.py`

초당 172개의 raw 측정치를 그대로 그리면 바늘이 떨린다. 정책 4단:

1. **신뢰도 게이트**: confidence < 0.5 → 표시 불변. 6프레임(35ms)까지
   직전 값 유지(hold), 이후 SILENT/NOISY.
2. **점프 확인**: 직전 표시값과 **80cent 이상** 차이 → 즉시 안 따라가고
   **2프레임 연속 일치** 요구(1프레임 옥타브 글리치 차단). 확인되면
   스무딩 필터를 리셋하고 **즉시 스냅** — 그래서 음 전환 반응(~40ms)은
   스무딩과 무관하게 유지된다(스윕 전 구간에서 39.9ms 불변 실측).
3. 80cent 미만의 변화는 ↓
4. **One-Euro 스무딩** (cents 도메인, 속도 적응 저역통과):
   - 거의 정지(지터 ~35c/s) → 컷오프 1Hz, 바늘이 고요
   - 빠른 변화(비브라토 ~690c/s) → 컷오프가 β·|속도| 만큼 열려 통과
   - 채택값 (min_cutoff=1.0Hz, β=0.04): 지터 p95 0.94→0.52c,
     비브라토 진폭 85% 보존, 글리산도 지연 38ms.
     전체 그리드 실측은 [smoothing-tuning.md](smoothing-tuning.md).

## 4b. 음이름 래치 — `core/notes.py` (NoteLatch)

주파수가 반음 경계 근처에 머무르면(= 악기가 많이 어긋난 상태 = **튜닝
중일 때**) 비브라토 한 사이클마다 이름이 C6↔C#6 으로 뒤집힌다. 두 겹의
가드로 막는다:

- **히스테리시스 15¢**: 경계(±50¢)를 15¢ 더 넘어야 변경을 *고려*
- **dwell 12프레임(~70ms)**: 그 밖에 연속으로 머물러야 실제로 변경

유지 중에는 cent 가 ±50 을 넘어 표시되고(바늘은 끝에서 클램프) "눈금
밖으로 나갈 만큼 높다/낮다"로 읽힌다.

> 실측(플루트 vib C6, 실제로 C6+30~70¢): 래치 없음 15세그먼트 →
> (15¢, 12) 조합에서 3세그먼트. 대가는 진짜 반음 변화 시 **이름**이
> 110ms 늦게 바뀌는 것 — 바늘·cent 는 즉시 반응하므로 체감 지연 아님.
> 히스테리시스만 키우면(25¢) 정말 어긋난 음을 못 알아채고, dwell 만
> 키우면 이름 지연이 커진다.

## 5. Hz → 음이름 + cent — `core/notes.py`

주파수는 로그 스케일이므로:

```
midi실수 = 69 + 12·log₂(f ÷ A4기준)
음이름   = round(midi실수)          # 69 = A4
cent     = (midi실수 − round) × 100
```

예: f=442.00, 기준 442 → 정확히 69.0 → A4 +0.0¢.
기준이 440이면 69.078 → A4 **+7.84¢** (초록 구간 ≤8을 아슬하게 통과).

## 6. 표시 — `app/`

`TunerReading`이 오디오 스레드에서 Qt 큐드 시그널로 GUI 스레드에 전달:

- **미터**: 바늘 각도(cent×1°), cent 뱃지, 색(|c|≤8 초록 / ≤15 주황 /
  빨강). 소리가 멎으면 마지막 값을 4초간 반투명 고스트로 유지.
- **트레이스**: 리딩 개수 기준 x축(무입력 시 정지), 음 경계 점선+음이름.

## 전체 지연

창 절반(23ms, 측정치는 창 중심을 대표) + 계산(≈0.1ms) + 점프 확인
2프레임(12ms) ≈ **음 전환 후 바늘 도착까지 ~40ms** (기준 100ms).

## 표시 안정화 스위치

체감을 비교하거나 검출 원본을 보고 싶을 때 한 줄로 끈다:

| 기능 | 스위치 |
|---|---|
| One-Euro 스무딩 | `core/tracker.py` : `SMOOTHING_ENABLED = False` |
| 음이름 래치 | `core/notes.py` : `NOTE_LATCH_ENABLED = False` |
| 입력 레벨 게이트 | `core/detector.py` : `INPUT_GATE_RMS = 0.0` |

## 정답(ground truth)의 신뢰 구조

실오디오 테스트의 "정답"은 우리 주석기가 만든다. 따라서 "앱과 주석기가
일치"만으로는 **둘이 같은 방향으로 틀린 경우**를 못 잡는다. 특히 앱의
`restore_weak_fundamental` 과 주석기의 `estimate_f0` 는 옥타브 판정
로직 `divide_to_true_f0` 를 **공유**한다(게이트 1.2% vs 10%, 창 길이·
인과성은 다름). 이 공유 지점이 틀리면 양쪽이 함께 틀릴 수 있다.

그래서 우리 코드 밖의 권위 두 가지로 감시한다
(`tests/dsp/test_crossvalidate.py`):

1. **녹음 자체의 라벨** — Iowa MIS 파일명이 연주된 음을 명시한다
   (`violin/A4.flac`). 녹음자가 붙인 외부 라벨이라 옥타브·음이름을
   절대적으로 고정한다. 뱅크 100클립 + 단음 픽스처 전부 검증(최악 38¢,
   연주자의 조율 편차 범위).
   여기에 더해 **제3자 데이터셋 TinySOL**(IRCAM, CC-BY-4.0) 8악기 96클립을
   그 저자들의 라벨로 검증한다(`tests/fixtures/external/`). 우리가 고르지
   않은 악기·주법이라 미지의 음색에서의 드리프트를 잡는다. 부수적으로
   이 클립들의 편차 중앙값이 데이터셋의 조율 기준을 드러낸다(A4≈440.4Hz).
2. **독립 구현** — librosa `pyin`(다른 저자, 다른 코드베이스)과 대조.
   불일치 시 1번이 심판. 실측: 100클립 중 98개가 5.1¢ 이내 일치,
   불일치 2개는 **둘 다 오보에이고 pyin 이 배음을 잡은 것**(라벨이 우리를
   지지) — 우리가 고쳤던 약한 기음 함정에 pyin 이 그대로 빠진다.
3. **음향 루프백**(`tests/e2e/test_acoustic_loopback.py`) — 정확히 아는
   주파수를 스피커로 재생해 마이크로 녹음. 음향 경로는 주파수를 바꾸지
   않으므로 정답이 산수로 확정되면서 실제 룸·마이크 특성이 포함된다.
