# 녹음 — 설계 결정과 구현

**언제 읽나**: 녹음 기능(연주 녹음·저장·목록)을 만들거나 손볼 때.

목업과 비교표는 [recording-ui-options.html](recording-ui-options.html) 이
원본이다 (브라우저로 열면 실제 크기 310×190 목업이 보인다). 이 문서는 그
결과만 정리한다.

## 녹음과 리포트는 다른 기능이다

이 앱에는 캡처가 둘 있고, **이름이 겹치면 반드시 혼동된다**:

| | 리포트 | 녹음 |
|---|---|---|
| 누구를 위한 것 | 개발자 | 연주자 |
| 무엇을 담나 | 오디오 + 그때 미터가 보인 것 + 코드 sha | 오디오만 |
| 어디로 | `~/.tuner/reports/` (숨은 폴더) | 음악 ▸ Tuner (찾을 수 있는 곳) |
| 형식 | WAV (무손실, 다시 분석할 것) | OGG Vorbis (들을 것) |
| 키 | `Ctrl+R` · `Ctrl+Shift+R` | `Alt+R` · `Alt+P` · `Alt+S` |
| 구현 | `app/capture.py` `FieldCapture` | `app/recorder.py` `Recorder` |

**수정자가 기능군을 가른다** — `Ctrl` 은 리포트, `Alt` 는 녹음. 이 규칙이
있어서 키가 늘어도 서로를 침범하지 않는다.
`tests/invariants/test_shortcuts.py` 가 충돌을 막는다.

### 서랍은 윈도우 음성 녹음기의 모양이다 (2026-10-03 개정)

사용자가 이미 쓰고 있는 녹음기가 기준이다. 페이지 셋을 `QStackedWidget` 으로
갈아 끼운다:

| 페이지 | 무엇이 있나 |
|---|---|
| **목록** | 날짜별로 묶인 녹음(제목 / 날짜·시각 / 길이), 아래 가운데 **큰 마이크 원** |
| **녹음 중** | `00:00:01` 시계, 입력 레벨 띠, **고리 두른 정지 원**, 아래 일시정지 |
| **재생** | `←` 뒤로, 제목·날짜, **재생/일시정지 원**, 탐색 바, 이름·삭제·폴더 |

색만 이 앱의 것으로 바꿨다. 윈도우는 녹음도 재생도 파란 원이지만, 여기서는
**녹음은 빨강**(바늘이 이미 쓰는 색이고 녹음 버튼의 보편적인 색), 재생은
차분한 파랑이다.

행을 누르면 **재생을 시작하지 않고** 재생 페이지를 연다 — 윈도우 녹음기와
같다. 누른 행은 보려고 누른 것이지 늘 들으려고 누른 것은 아니다.

**녹음에 관한 모든 문구는 서랍 안에서 뜬다.** 튜너의 알림 줄은 튜너의 것으로
남는다.

### 서랍이 하나인 이유

녹음 컨트롤과 목록을 따로 두면 창에 상태가 둘 생긴다. 하나로 합치면
**열림/닫힘 하나**이고, 여는 방법만 둘이다(`●` 는 녹음까지 시작, 손잡이는
목록만). 본체는 언제나 310×190 이고 서랍은 그 오른쪽에 덧붙는다.

접힘 상태는 A4·장치·BPM 과 같이 `QSettings` 에 남는다.

### 창 크기 — 가로는 그대로, 세로는 빌려준다

한때 컨트롤 줄에 `●` 를 놓고 손잡이를 레이아웃에 넣어 창 바닥이 294 → **331**
이 됐다. 둘 다 되돌렸다: 녹음 컨트롤은 서랍 안으로 갔고, 손잡이는 미터 오른쪽
가장자리에 **겹쳐 그린다**(그 11px 띠는 미터 호 바깥의 빈 여백이다). 닫힌 창은
다시 **310 × 190, 바닥 294** — 녹음 기능이 생기기 전과 같은 숫자다.

세로는 다르다. 190px 안에 녹음 목록은 들어가지 않는다(실측: 행 한 개 반이
스크롤바 뒤에 깔렸다). 그래서 서랍을 열 때 창 높이를 **360 이상으로** 올리고,
닫을 때 **원래 높이로 되돌린다**. 튜너만 쓸 때는 1px도 더 높지 않다.

### 서명 (결정 4)

Vorbis 주석 필드에 `SOFTWARE=tuner`, 녹음 시각, 그때의 **A4 기준**을 적는다.
목록은 폴더가 아니라 **이 서명으로** 거르므로, 사용자가 음악 파일을 그 폴더에
복사해 넣어도 목록에는 뜨지 않는다. 음악 폴더는 사람이 드나드는 곳이라
(결정 8) 이 구분이 실제로 필요하다.

덤: A4 기준이 남으니 그 녹음을 나중에 `trace`·`annotate` 로 다시 분석할 때
**당시 기준으로** 채점할 수 있다.

## 구현된 모습 (2026-10-03)

| 조각 | 어디 |
|---|---|
| 소리 모으기·일시정지·저장·목록·서명·날짜 묶기 | `app/recorder.py` (Qt 없음, 폴더 찾기만 예외) |
| 서랍 — 목록/녹음 중/재생 세 페이지 | `app/recordings_drawer.py` |
| 큰 원형 버튼(마이크·정지·재생·일시정지) | `app/round_button.py` (글리프는 그린다) |
| 반달 탭 손잡이 | `app/drawer_handle.py` |
| 저장 창 | `app/save_take_dialog.py` |
| 재생(위치·탐색·일시정지) | `app/take_player.py` (`AudioOutput` 심을 그대로 씀) |
| 조립·단축키·상태 | `app/main_window.py` |

**녹음은 디스크에 흘려 쓴다.** 오디오 스레드는 블록을 큐에 넘기기만 하고, 테이크마다
하나씩 뜨는 쓰기 스레드가 저장될 폴더 안의 숨은 `.take-*.part` 파일에 Vorbis 로
인코딩해 쓴다. 중지하면 그 스레드를 비우고 파일을 닫으며, 저장은 **이름 바꾸기**,
버리기는 **삭제**다. 처음엔 테이크 전체를 메모리에 들고 있다가 중지할 때
인코딩했는데, 상한이 없었고(float32 분당 ~10.6MB, 한 시간 ~635MB, 중지 순간 두 배),
그 인코딩 동안 창이 멈췄고, 합치는 사이 들어온 마지막 블록이 버려질 수 있었다.
흘려 쓰기는 셋을 뿌리에서 없앤다. 녹음 중인 `.part` 는 `.ogg` 가 아니라서 목록에
뜨지 않는다.

엔진은 블록 싱크를 하나 더 받는다(`recorder=`). 리포트 캡처와 **나란히** 돌고
서로를 모른다 — 하나는 개발용 증거를, 하나는 연주를 쓴다.

### 구현하면서 실측으로 드러난 것

- **제목은 파일명으로.** Vorbis 주석의 `title` 에 한글을 쓰면 읽을 때 깨진다
  (`테스트 제목` → 모지바케). 파일명은 양쪽 OS 에서 멀쩡하므로 제목은 거기
  싣고, 태그에는 ASCII 만 둔다.
- **서명은 접두사로 비교한다.** libsndfile 이 자기 버전을 붙여
  `SOFTWARE` 가 `"tuner (libsndfile-1.2.2)"` 로 읽힌다.
- **창 폭 바닥이 294 → 331.** 손잡이 11 + 컨트롤 줄의 `●` 26(버튼 22 + 간격 4).
  기본 310 과 바닥 294 사이 여유 16 으로는 모자랐다.
- **서랍을 닫아도 창이 안 줄었다.** 서랍을 띄우면 Qt 가 레이아웃 최소값을 창의
  *명시적* `minimumWidth` 로 써 버리고, 숨겨도 안 내린다. `setMinimumWidth(0)`
  으로 풀면 다음 패스에서 레이아웃이 자기 값을 다시 쓴다.
- **녹음 패널이 창을 10px 높였다.** 목록이 자기 최소 70px 아래로 안 내려가서.
  목록을 줄어들 수 있게 해 막았다.
- **목록 행이 13px 로 찌그러졌다.** `QPushButton` 은 자기 글자로만 크기를 정하고
  안에 넣은 레이아웃을 보지 않는다. `sizeHint` 를 레이아웃에 위임해 고쳤다.
- **입력 게이트는 녹음에 안 걸린다.** 엔진이 블록을 받으면 **맨 먼저** 녹음기로
  넘기고, 게이트는 그 뒤 `YinDetector.detect` 안에 있다. 의도한 대로다 — 게이트는
  "이걸 음으로 판정할까"이지 "이걸 남길까"가 아니다. 여린 패시지가 잘리면 안 된다.
  불변식으로 봉인했다.

## 만들 때 지킬 것

- **정답 데이터 먼저** (`docs/process/ground-truth.md`). 이 영역은 정답이
  산수로 확정된다 — 아는 신호를 녹음해 다시 읽으면 같은 신호여야 한다.
  메트로놈과 같은 종류라 주석기가 필요 없다.
- **불변식** — `tests/invariants/test_recording_truth.py` 에 봉인됨:
  저장한 파일의 길이 = 녹음한 시간, 일시정지한 구간은 결과에 없다,
  일시정지를 몇 번 하든 이어붙인 길이가 맞는다, 서명 없는 파일은 목록에 안 뜬다,
  같은 이름이 와도 앞 녹음을 덮지 않는다, **입력 게이트는 녹음에 닿지 않는다**,
  그리고 **손실 압축을 거쳐도 검출되는 피치는 ±2¢ 안**(E2~E6 실측).
- **구조**: 녹음은 `app/` 의 조립이고 서랍은 위젯이다. `core/` 는 녹음을
  모른다 — `tests/invariants/test_layering.py` 가 자동으로 잡는다.
- 테스트가 진짜 음악 폴더를 건드리지 않도록 `TUNER_RECORDINGS_DIR` 로
  덮어쓴다 (`TUNER_REPORTS_DIR` 과 같은 방식).

## 맥에서도 똑같이 돈다 (제약)

이 앱은 Windows 와 macOS 양쪽에서 쓰인다. 플랫폼 분기를 만들지 않는 것이
기존 방침이고(`docs/ARCHITECTURE.md` "플랫폼 분기 없음"), 녹음도 예외가
아니다. 다만 위 결정 중 **셋은 OS 가 다르게 해석**하므로 짚어둔다.

| 결정 | Windows | macOS | 상태 |
|---|---|---|---|
| 폴더 (8) | `C:\Users\<이름>\Music\Tuner\` | `~/Music/Tuner/` | ✅ `QStandardPaths.MusicLocation` 이 알아서 맞춘다 |
| `Ctrl+*` (7) | Ctrl | **⌘ (Command)** | ✅ Qt 의 기본 매핑이고, 맥에서 더 자연스럽다 |
| `Alt+*` (7) | Alt | **⌥ (Option)** | ⚠️ 아래 참조 |
| 형식 (5) | libsndfile Vorbis | 같음 | ✅ 같은 `soundfile` 휠 |

### ⌥ 에 대한 경고와 대안

맥에서 `Option+R·P·S` 는 텍스트 입력 중이면 `®` `π` `ß` 를 낸다. 본체 창에
입력 칸이 없어서(A4 는 읽기 전용, 템포는 별도 다이얼로그, 제목은 모달 안)
단축키로 동작할 것으로 보지만 **실측하지 않았다**.

**맥에서 아직 확인하지 않았다 — 처음 열어볼 때 이것부터.** 셋 다 안 먹거나
특수문자가 끼어들면
대안은 `Ctrl+Alt+*` 가 아니라 — 그건 맥에서 ⌘⌥ 가 되어 더 어색하다 —
**`Ctrl+1 / 2 / 3`** 처럼 수정자를 Ctrl 로 통일하고 숫자로 가르는 쪽이다.
그 경우 "수정자가 기능군을 가른다"는 규칙은 깨지지만, 맥에서 안 눌리는
키보다는 낫다. 어느 쪽이든 `tests/invariants/test_shortcuts.py` 가 충돌만은
막는다.

### 그 밖에 맥에서 다른 것

- **마이크 권한** — 녹음은 이미 열려 있는 입력 스트림을 쓰므로 새로 요구하는
  권한은 없다. 권한이 없을 때의 안내는 기존 무음 배너가 그대로 담당한다.
- **창 넓어짐** — 맥의 전체화면/스테이지 매니저에서 always-on-top 창이
  넓어지는 체감이 Windows 와 다를 수 있다. 서랍이 **오른쪽으로만** 열리는
  이유가 본체 위치를 고정하는 것이라, 양쪽에서 같은 규칙으로 동작한다.
- **e2e 는 양쪽 CI 에서 자체 skip** 된다. 녹음의 장치 의존 부분도 같은
  관례를 따른다 — 하드웨어가 없으면 스스로 빠지고 이유를 말한다.

## 확인하지 않은 것

- 위 **⌥ 단축키의 맥 실동작**. 맥에서 처음 열어볼 때 첫 번째로 확인할 것.
- **화면이 잠긴 기계에서는 e2e 스태킹 테스트가 자체 skip** 된다 — 창이 아예
  매핑되지 않아 `topLevelAt` 이 아무것도 못 찾는 상태를 실패와 구분한다.
- **always-on-top 창이 넓어지는 것** 자체가 비용이다. 화면 오른쪽 끝에 붙여
  쓰는 경우 공간이 모자라면 창 전체가 왼쪽으로 밀리는 처리가 필요하다
  (양쪽 OS 공통).
