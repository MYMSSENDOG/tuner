# 회귀 봉인

**언제 읽나**: 피처 개발을 시작/마무리할 때, 사용자가 겪은 버그를 고칠
때, 판정 기준·파라미터·임계값을 정하거나 바꿀 때.

## 규칙

- 피처 시작 전과 후에 **전체 스위트 그린**. 새 피처도 기존 테스트
  데이터셋 위에서 채점되어야 한다.
- 사용자가 겪은 결함은 **수정 전에 재현 테스트부터** 만든다.
  (실례: 표시 깜빡임이 두 번 제기될 동안 회귀 감시가 없었다.)
- **검정력 확인**: 기능을 끄면 관련 테스트가 실제로 깨지는지 확인한다.
  깨지지 않는 테스트는 그 기능을 지키고 있지 않은 것이다
  (`test_stabilization_is_actually_doing_something` 패턴).
- 판정 기준을 완화할 때는 **드라이버**(어느 데이터의 어떤 실측값이 이
  값을 결정했는지)를 주석으로 남긴다. 개선이 누적되면 되조인다
  (실례: 저음역 특례 20¢ 가 개선 후 불필요해져 제거).
- 파라미터·임계값은 감이 아니라 **그리드 스윕 실측**으로 정하고 결과
  표를 `docs/` 에 남긴다 (실례: `docs/smoothing-tuning.md`).
- **스팟 측정만으로 임계값을 정하지 않는다** — 몇 개 클립에선 깨끗했던
  분리 기준이 코퍼스 전체(300+)에선 실패해 되돌린 사례가 있다.

## 완료의 정의

"고쳤다" = 원인을 실측으로 특정 + 재현 테스트 존재 + 전체 스위트 그린.
셋 중 하나라도 없으면 아직 안 끝난 것.
