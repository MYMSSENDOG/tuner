# 정답 데이터 먼저 (Ground Truth First)

**언제 읽나**: 새 알고리즘/기능 영역에 들어갈 때, 새 테스트 데이터가
필요할 때, "정답을 어디서 가져오지?"라는 질문이 생길 때.

## 규칙

새 영역의 구현을 시작하기 전에 네 가지를 먼저 갖춘다:

1. **진실이라 말할 수 있는 테스트 데이터** — "학교종이 땡땡땡 수준이라도,
   몇 초부터 몇 초까지 몇 Hz 인지" 상세하게 기록된 데이터.
2. **그 데이터를 만들어 내는 능력** — 도구화되어 반복 가능해야 한다.
3. **그 데이터가 진실인지 검증하는 능력** — 정답 생성기 자신도 검증
   대상이다. 우리 코드 밖의 권위(수학적 유도, 제3자 라벨, 독립 구현,
   물리 법칙)와 대조한다.
4. **그 데이터로 앱을 채점하는 하네스.**

구현을 먼저 하고 테스트를 나중에 붙이지 않는다.

## 함정

정답 생성기와 앱이 로직을 공유하게 되면 "일치 = 정답"이 무너진다
(실례: `divide_to_true_f0` 공유). 공유가 불가피하면 문서에 명시하고
외부 권위로 감시한다.

현재 갖춰진 정답 체계(합성 신호 / 실악기 주석 / 제3자 라벨)와 그 신뢰
구조·실례는 `docs/pitch-pipeline.md` "정답의 신뢰 구조" 절이 원본이다 —
여기 중복하지 않는다.
